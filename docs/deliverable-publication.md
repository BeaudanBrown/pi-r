# Versioned deliverable publication

Pi-r separates target execution from source-control publication. Running a target may update its exact sandbox-writable output and the `_targets/` cache, but it never stages or commits generated files.

## Contract declarations

The optional `deliverables` array names the only generated outputs eligible for publication:

```json
{
  "deliverables": [
    { "target": "report", "path": "artifacts/report.html" }
  ]
}
```

Each entry must refer to a non-dynamic `file` target and exactly match that target's single constant output path. Paths are bounded portable project-relative paths. Traversal, redundant segments, runtime directories, Git internals, machine-owned files, and source directories are rejected. Deliverable paths and target names are unique.

The generated `.gitignore` contains only known runtime paths and exact undeclared file-target outputs. It does not use blanket patterns for arbitrary untracked files. Declared deliverables remain visible to Git, while table/object artifacts remain in the ignored `_targets/` store.

## `/r publish`

Publication is a user-only approval boundary in Implementation Mode. `/r publish`:

1. verifies the Workbench branch, HEAD, locked contract, and generated scaffold;
2. rejects a non-empty index and unrelated tracked changes while leaving unrelated untracked files alone;
3. lists freshness through the read-only Target Runner and accepts only current declared targets;
4. canonicalizes each changed path and rejects missing files, directories, symlinks, hard links, escapes, and bounded-size violations;
5. previews sorted status, byte size, SHA-256 identity, and a bounded text diff or binary/large-file marker; and
6. asks the user for explicit confirmation.

Cancellation changes neither files nor Git. After confirmation, pi-r repeats freshness, path, content, and HEAD validation. It stages exact declared paths with Git pathspec termination, verifies the complete staged path set, and creates one provenance commit:

```text
Publish declared deliverables

Capability: r_deliverable_publish
Deliverables: artifacts/report.html
Publication-Digest: sha256:...
```

Any staging or commit failure resets only the candidate deliverable paths from the index and leaves working outputs available for recovery. A successful publication updates Workbench provenance without restarting the Persistent R Worker or modifying the target cache.

Previously published deliverables may be regenerated by their declared target. Target execution grants this narrow tracked-output exception but still rejects every other tracked path as well as symbolic or hard-linked outputs. A later `/r publish` is required to commit the new bytes.
